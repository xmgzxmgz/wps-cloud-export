# WPS Cloud Export

批量导出 WPS / 金山文档云文档到本地的 Web 工具。

## 功能

- 📄 **云文档** — 我的云文档、自动上传文档，递归遍历文件夹，树形浏览
- 💻 **设备文档** — 按设备查看所有同步文件（PC / 手机 / 平板），支持选择下载
- 📦 **批量打包** — 勾选文件后打包为 ZIP 一键下载，实时进度
- 🔐 **Cookie 登录** — 粘贴浏览器 `wps_sid` 即可，无需安装任何软件
- 🎨 **shadcn/ui 风格** — 深色主题，现代 UI
- 🐳 **Docker 部署** — 一行命令启动

## 快速开始

### Docker（推荐）

```bash
docker compose up -d
```

打开 http://localhost:5800

### 直接运行

```bash
pip install -r requirements.txt
python app.py
```

## 权限说明（重要）

本工具导出的是**你当前账号有下载权限**的文件。下载地址由 WPS 服务端按权限下发，客户端无法代劳：

| 场景 | 能否导出 | 说明 |
|------|---------|------|
| 我的云文档 / 自动上传文档 / 设备文档 | ✅ | 自己的文件，正常下载 |
| 他人共享给你、且允许下载的文档 | ✅ | 只要服务端下发下载地址就能导 |
| 他人共享给你、设置为「只能查看」的文档 | ❌ | 服务端不返回下载地址（或直接 403），这是所有者的权限设置 |
| 企业管理员开启水印/禁止下载的文档 | ❌ | 同上，受企业策略控制 |

对最后两类，工具会明确提示「无下载权限：该文件可能为他人共享的只读文档，或所有者已禁止下载」，而不是笼统报「下载失败」。

需要离线留存时，合规且可用的做法是：在浏览器里打开该文档，用 **打印 → 另存为 PDF**，或向所有者申请可下载权限。

## 获取 Cookie

1. Chrome 打开 [www.kdocs.cn](https://www.kdocs.cn) 并登录
2. 按 `F12` → **Application** → **Cookies** → **kdocs.cn**
3. 复制 `wps_sid` 的值（可选也复制 `csrf`）
4. 粘贴到网页登录框

## 技术栈

- **后端**: Python / Flask / Gunicorn
- **前端**: Tailwind CSS（shadcn/ui 设计风格）
- **部署**: Docker / docker-compose

## API

| 端点 | 方法 | 说明 |
|------|------|------|
| `/api/login` | POST | 验证登录 |
| `/api/groups` | GET | 云文档组 |
| `/api/file-tree` | GET | 文件树 |
| `/api/device-list` | GET | 设备列表 |
| `/api/device-files` | GET | 设备文件 |
| `/api/download` | GET | 下载单文件 |
| `/api/batch-download-zip` | POST | 批量 ZIP |
| `/api/batch-progress` | POST | SSE 进度 |

## 注意事项

- Cookie 有效期有限，过期后需要重新获取
- 频繁下载可能触发限流，建议控制批量数量
- 只读共享文档无法导出（见[权限说明](#权限说明重要)），这不是工具的缺陷
- 本工具仅供个人数据备份，请遵守 WPS 服务条款

## 常见问题

<details>
<summary><b>Q：能导出别人共享给我的「只能查看」文档吗？</b></summary>

不能，也不打算做。

这类文档的下载权限由所有者在服务端设置，WPS 不会给只读访问者下发下载地址。绕过它需要伪造权限或抓取渲染内容，前者违反服务条款、后者只能得到排版错乱的残缺副本。工具会明确提示「无下载权限」，方便你判断到底是网络问题还是权限问题。

可行的替代方案：
1. 浏览器打开文档 → **打印 → 另存为 PDF**（保真度最高，只读文档也适用）
2. 向所有者申请「可下载」或「可编辑」权限后，用本工具批量导出
3. 如果是团队协作文档，让所有者把它放进团队共享空间并开放下载
</details>

<details>
<summary><b>Q：批量下载时部分文件失败，怎么区分原因？</b></summary>

现在每条错误都会带上具体原因：

- `无下载权限：该文件可能为他人共享的只读文档，或所有者已禁止下载`
- `Cookie 已过期，请重新获取 wps_sid`
- `文件不存在或已被移动/删除`
- `服务端未返回下载地址（该文件可能不允许下载）：msg=… result=…`（附原始返回，便于排查）

批量结果和 SSE 进度里都会显示这三种之外的真实原因，不再统一显示「下载失败」。
</details>
